## E4 场景抓到、单测漏掉的两个真问题（这轮 E4 的价值所在）

1. **被拒绝的发布会留 `.part` 残留**。首轮 `upload-no-replace` FAIL 在
   `part_artifacts_remaining`（期望 0，实际 1）：`commit_upload` 在 `hard_link` 因目标
   已存在而失败时直接返回错误，把暂存文件留在磁盘上。12 条单测当时全绿——因为
   `publish_never_overwrites_an_existing_target` 只检查了"原字节没被动过"，没检查残留。
   修法是发布被拒即 `abort_upload`（删 `.part`、撤流），并补了一条单测锚住。
   刻意与"页级拒绝"区分：后者要保留已承认前缀供续传（G18），而"目标已存在"这条流
   永远不可能成功，留着只会变成无人负责的中转字节。
2. **探针自己的 fixture 不自洽，被 G12 交叉约束拒启动**。`quota-backpressure` 首轮 FAIL
   在 `verdict`，实际错误是 `CONFIG_INVALID: max_ack_bytes must be <= max_buffered_amount`
   （我把 `max_buffered_amount` 压到 128 却没同步压 ack 上限）。这不是引擎缺陷，而是
   配置门确实在拒——契约要的就是这个行为，探针之前没走到。修法是把 fixture 写全。

另外一条流程事实：`overflow_code` 原本在探针里是把常量抄回 JSON（`json!(code::QUEUE_FULL)`），
那样 `queue_full_reported` 就成了自证。已改成报告实际拿到的错误码。

其中一条我已**独立取证确认**（不是采信评审者）：V2 §1④b 的"SFTP 提交显式携带
no-replace 标志"在 ssh2 0.9.6 上是**空操作**。取证命令与输出（Linux，libssh2 1.0.0）：

```
include/libssh2_sftp.h:51: #define LIBSSH2_SFTP_VERSION 3
src/sftp.c:2800:  _libssh2_sftp_rename_ex(..., unsigned int flags, ...)
src/sftp.c:2833:  if (flags && sftp->version >= 5) {
src/sftp.c:2834:      /* version 5 of the SFTP protocol adds a few interesting flags */
grep -n "sftp->version *=" src/*.c   → 无任何赋值（通告即 LIBSSH2_SFTP_VERSION=3）
src/sftp.c:2827:  if (libssh2_sftp_handle... SSH_FXP_RENAME ... use it.
```

⇒ `Some(ATOMIC|NATIVE)` 与 `None` 的包体逐字节相同；真正的无覆盖改名原语是
`SSH_FXP_POSIX_RENAME`（`libssh2_sftp_posix_rename_ex`，sftp.c:3033），ssh2 0.9.6 未包装。
因此 **G14/REQ-008 里"SFTP 显式 no-replace"这一句必须重写**：要么 (a) SFTP 面只提供
"发布到一个不存在的路径"且用唯一名 + 事前 stat 检查（仍有竞态，须写明），
要么 (b) 在拿到可用的 no-replace 原语之前**根本不支持 SFTP 上传**（fail-closed，推荐），
要么 (c) 走依赖治理给 ssh2 加 `posix_rename` 绑定。这条属于契约文本纠正，
需要 requirement-change 口径，不能靠实现细节回避——owner 拍板后改。

其余待办（按评审给的阻塞序）：错误码词表在 V2 设计与冻结契约之间分叉

## 关于 `verify --full` 的 `product-scenarios` 门（一处更正）

"FAIL ⇒ 门 FAIL；run/parse 失败 ⇒ UNKNOWN（绝不静默 PASS）"，而 M0 的失败形态是
`failed_step=parse`（探针不存在，stdout 为空）⇒ 记 UNKNOWN，不阻塞。
