## C. 契约哈希口径勘误（与 .agents/red-evidence-code-intelligence.txt 文末一致）

第一轮记录里 `contract=096be167075d…` 是 **Windows 工作树字节**值：`.gitattributes` 为
`* text=auto`，只有 git checkout 的文件转 CRLF、由工具写入的文件保持 LF，所以该值既不可
在 Linux 复现，也不可在重新 checkout 后复现。已验证的复现口径是对**已提交 tree 的 LF blob**
按 `Repo::contract_hash()` 的拼接顺序（目录名与文件名排序，段间 `\n===\n`）喂
`git hash-object --stdin`：

    d4138b7（契约冻结，277+9 个场景）= f13e96c681a6aa3c354896fade811d65d613f96b
    1f88158/…/6aadc42（+budget_count）= 9b250ff2927b34af8db94120560b14be7950ac81

Linux 上 `nexus-harness status --json` 的 live `contract_hash` 实测等于第二个值，
证明该口径与实现一致。复现脚本：本仓库外的 /d/next/contract-hash.js。
